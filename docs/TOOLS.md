# ReMCP tool reference

> Generated by `scripts/generate-web-tool-docs.mjs` from the production MCP catalog. Do not edit this file by hand.

The production catalog advertises **15 hosted tools** when custom widgets are enabled, but only **10 are model-visible**: **8 device-facing façade tools** plus **2 account/fleet tools**. The remaining **5 tools are app-only UI helpers** for preview hydration, file-editor save, and terminal refresh. Those compact definitions route to **83 granular runtime operations**. Cached clients can still call legacy granular names, so the compatibility call surface contains **105 unique names** without forcing a model to choose among all of them. Setting `REMCP_CUSTOM_WIDGETS_ENABLED=false` exposes the same 10-tool model-facing surface without app-only helpers or preview metadata. Hosted discovery stays release-stable; each connected computer advertises its exact live runtime subset through `list_devices`, and the server checks the selected operation against that device immediately before dispatch.

The app-only helpers never add model-selected action paths: render tools rehydrate already-returned file/image/terminal previews, `save_file_preview` writes the exact editor contents through the underlying `write_file` schema, and `refresh_terminal_preview` reads more output through the underlying `read_process_output` schema.

For visible interaction, use **Accessibility/UI Automation → browser DOM/CDP → OCR → coordinates**. Prefer structured document tools over automating Office applications when the task is about file content rather than interactive formatting.

Required parameters are marked with `*`. Tool descriptions, parameter names/types, and safety hints below come from the same catalog that the server advertises.

## Account & fleet

List paired computers and use one account lane for profile, usage, hosted configuration, pairing, ping, rename, enable/disable, or removal.

| Tool | Safety | Parameters | When to use |
| --- | --- | --- | --- |
| `list_devices` | read-only | None | Use this when the target computer is not already unambiguous. Call it first to list computers paired to the signed-in ReMCP account and see which ones are online. |
| `manage_account` | changes state | `operation*` ("profile" \| "recent_calls" \| "usage" \| "configuration" \| "pair" \| "ping" \| "rename" \| "enable" \| "disable" \| "remove"), `device` (string), `name` (string), `limit` (number ≥1 ≤100), `days` (number ≥1 ≤90), `tool` (string) | Use this when the task concerns the signed-in ReMCP account or paired-computer membership: inspect profile, recent calls, usage or hosted configuration; create a pairing; or ping, rename, enable, disable, or permanently remove one pairing. Use list_devices first when the target computer is ambiguous. Local runtime preferences belong to manage_system. |

Operations: `profile`, `recent_calls`, `usage`, `configuration`, `pair`, `ping`, `rename`, `enable`, `disable`, `remove`

## App-only UI helpers

| Tool | Safety | Parameters | When to use |
| --- | --- | --- | --- |
| `render_file_preview` | read-only | `preview_id*` (string) | Use this when the file preview app needs to recover from late or missing result metadata. | `render_image_preview` | read-only | `preview_id*` (string) | Use this when the image preview app needs to recover a read_image or screenshot result from late or missing result metadata. | `render_terminal_preview` | read-only | `preview_id*` (string) | Use this when the terminal preview app needs to recover from late or missing result metadata. | `save_file_preview` | changes state | `path*` (string), `content*` (string), `mode` ("rewrite" \| "append"), `device*` (string) | Use this when the ReMCP file preview app needs to save the user-edited contents back to that same paired computer. ## Contract notes

- Every public tool has a human-readable title/description, explicit input schema, output schema for structured results, and MCP safety annotations in the production catalog.
- Structured tool calls return `structuredContent` that matches the advertised output schema together with normal MCP content where useful to the model.
- Browser/CDP tools are capability-aware and can be enabled or disabled as the local runtime discovers or loses a usable loopback browser endpoint.
- `computer_snapshot` is the broad first-look tool for an unfamiliar desktop; once the target is known, prefer the narrowest dedicated tool for the action and verify with semantic state before using pixels.
- The website renders this same catalog at [remcp.site/docs#tools](https://remcp.site/docs#tools).
